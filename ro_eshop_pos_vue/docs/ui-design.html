RO POS 界面设计规范

版本：v1.2 审阅稿 · 2026-10-02
状态：整体规范待审阅；取消后台重复大标题、POS 外围中性背景及后台统一间距已确认并实施。

本文件是后续界面升级的唯一设计基准。规范确认后，页面必须使用统一模板、组件与变量，不再逐页追加补丁调整观感。修改规范需先说明受影响页面，再同步实施和验收。

1. 范围与不变量

适用于开源单机版：POS 操作、业绩看板、订单与退货、商品与分类、本机设置、数据备份恢复，以及这些功能的编辑页和弹窗。

  • 不增加库存、云端、连锁门店或付费会员功能；已有升级入口不代表开源版可用能力。
  • 不改变本机账本、订单创建/导入、收款、退货或硬件协议。
  • POS 商品卡片内部布局、图片比例、文字、价格、角标保持原样；面板可用宽度变化允许卡片随原有网格分配宽度。
  • 中文及已有其他语言共用结构；主题仅改变颜色，不改变尺寸。
  • 不覆盖用户数据，不导入演示数据到实际使用的浏览器。
  • 本次只交付本设计文件。代码迁移、目录重构、发布与开源许可证选择不在本次执行范围内。

2.2 当前代码核查

  • package.json 声明 Vue、Element Plus、Vite、TypeScript；Element Plus 的声明范围为 ^2.14.7，这不是已验证的安装版本。
  • src/pure-admin.css 自述为 Pure Admin-inspired pilot surfaces；当前是参照样式的局部接入，尚不能称为完整官方模板迁移。
  • src/App.vue 承担工具栏、侧栏、标签页和页面切换；src/components/ 内存在不同页面外壳。
  • src/style.css、src/workbench.css、src/lists.css、src/pure-admin.css、src/theme.css 与组件 scoped 样式共同影响界面。
  • 标题既有 header > h2，也有直接 h2；商品页还有内层切换容器。相同间距依赖选择器层级补偿，容易遗漏。
  • 近期调整改善了部分页面，但本文件仍要求按完整模板重新验收，不将这些补丁当作最终架构。

3.1 Padding 归属：每一层只负责一次

后台工作区（左右 12）
└─ 页面外壳（padding 0、width 100%、无额外 max-width）
   ├─ 筛选卡片/设置正文（12；列表无重复标题）
   │  ├─ 字段行（padding 0；gap 8/16）
   │  └─ 操作行（上边距 8、上内距 8；左右 0）
   └─ 表格面板（与上一块 gap 8；外层 padding 0）
      ├─ 单元格（8 12）
      ├─ 合计（按表格列对齐）
      └─ 分页（8 12）

禁止“工作区 12 + 页面 12 + 多层 card 12”的重复包裹。中间只负责布局的容器统一 padding 0。完整宽度的底栏由结构实现，不以负 margin 穿透父级 padding。树导航内部搜索用 8px 是紧凑工具区的明确例外。

4. 字体、颜色与状态

沿用系统字体栈：-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif。

用途字号/行高字重
页面标题18/28px600
区块标题16/24px600
正文、控件、表格14/20px400；表头 600
说明、辅助信息12/18px400
快捷键提示10/14px 等宽400
POS 合计/结算金额沿用当前批准尺寸金额 600

数字使用等宽数字特性；订单号/条码按字符串显示，不丢前导零。金额右对齐并带币种；数量居中，日期与普通文字左对齐。订单号、会员、状态、收款方式各自一列；分类状态、级次各自一列，不再合并堆叠。

后台布局中性色不随蓝、橙、黑金主题漂移。品牌色仅用于主操作、选中、焦点与全局工具栏；主题映射统一取现有 --theme-*，不在页面散落硬编码。现有主题渐变仅限已有品牌工具栏/POS 结算等批准位置，后台普通按钮采用统一组件样式，不扩散渐变。

  • 工具栏版本、时间、图标均继承该工具栏前景色，不单独降低 opacity。
  • 未选中标签始终有边框和中性底色；选中标签保持相同尺寸。
  • 菜单分组标题使用中性浅灰；选中项使用独立浅蓝/浅橙/浅金底色及 3px 左侧主题色标记，悬停底色更淡。登录首页版权文字固定白色、无透明度，并加轻微深色阴影。
  • 购物车表头、顶部容器和列表空白使用同一表面色，不露出其他色带。
  • 状态不能只靠颜色区分，需保留文字；停用数据不能整行淡化到无法阅读。
  • 每个控件都有默认、悬停、键盘焦点、选中、禁用、加载、错误状态；焦点环不得直接删除。
  • 普通文字对比度目标至少 4.5:1；必要边界/焦点至少 3:1。三主题分别测量，不能以“继承主题”替代验证。

5. 标准页面模板

T1：普通列表（订单、退货、可查询的业务列表）

┌ 筛选字段：关键词  日期范围  常用条件                      ┐
│ 更多字段展开区（默认收起；已设置条件有数量提示）           │
├ 查询  重置  更多筛选       已选N条  批量操作  导出  创建等 ┤
└─────────────────────────────────────────────────────────┘
  8px
┌ 勾选 │ 序号 │ 独立业务字段…                  │ 行内操作 ┐
│                    列表主体独立滚动                     │
├ 筛选合计（如业务提供合计）                               ┤
└ 共N条                           每页条数  上一页  页码… ┘
  • 第一层只放筛选字段；第二层才放查询/重置/更多筛选和业务操作。按钮不得塞进关键词输入框。
  • 查询组在左、业务组在右；窄屏按组换行，不能靠巨大空白拉开单个按钮。
  • 列表有勾选和 Excel 导出；勾选时导出所选，无勾选时导出当前筛选结果，并明确范围。加载/无数据时给出禁用原因。
  • 翻页选择语义、跨页选择和导出范围必须一致且可见；改变筛选清除不再属于当前结果的选择并提示，不能静默操作隐藏记录。
  • 批量启用/停用保留商品及分类的已有业务规则；失败结果列出每条名称、标识及原因，区分成功/失败数量，不用一条笼统 toast 代替。
  • 表头固定，表格主体占剩余高度；合计与分页作为非滚动底部区域。合计为筛选总额还是勾选额必须明确标注。
  • 空列表与一条数据保持相同底部定位；不要拉伸数据行填空。
  • “订单创建/导入”继续生成本地待付款订单，不能因模板切换触发收款或写云端。

│ 树标题/收起      │     │ 查询组           业务操作组 │
│ 分类搜索（8px）  │     └────────────────────────────┤
│ 树节点独立滚动   │ 8px ┌ 列表独立滚动              │
│                  │     │                           │
└──────────────────┘     └ 合计/分页固定底部───────────┘

树面板与右侧筛选区同顶、与右侧表格面板同底。树收起后右栏完整占满；保留恢复入口。不恢复“全部展开/全部收起”按钮。分类树内部标题保留；取消上方与标签页重复的“商品管理/商品分类”标题，展开分类入口放在查询操作行。

T3：设置/数据管理

取消与标签页重复的设置大标题；顶部仅保留紧凑的保存操作栏，与设置表单连成一个外轮廓。表单内容 padding 12px，不再重复嵌套有 padding 的卡片。字段少时自然留白，不扩大控件填满空间。

  • 小票设置：编辑与预览并列，gap 8px；窄屏上下排列。打印纸张尺寸与打印 CSS 独立，不随页面密度改变。
  • 设备设置：内容宽度占满，字段两列；说明与校验贴近对应字段。保存与设备测试按钮分工清楚。
  • 主题设置：颜色选项和图片设置按功能分区，不改变设计规范的尺寸。
  • 数据管理：取消“数据管理”大标题，直接显示“本机单机账本”操作内容；导入、导出、演示数据与危险清理保持分组。数据说明与范围表间距 8px。JSON 备份不是 Excel 列表导出，标签不可混淆。
  • 币种、快捷键目前以弹窗/抽屉呈现，按 T5 统一；不因设计统一强制改为内页。

T4：编辑/详情/翻译

┌ 返回  标题                                保存/确认 ┐
├ 摘要或必要说明（12px）───────────────────────────────┤
│ 表单/详情主体，独立滚动                             │
│ 单语言字段块：名称/规格单行，描述按需多行            │
└────────────────────────────────────────────────────┘

仅一个返回入口，保存固定在页头；表单无需上下重复保存按钮。错误定位到对应字段，保存失败保留编辑内容。翻译语言块 gap 8px，内部 12px，不能让多层固定高度阻断滚动。详情页中收款等业务操作保持明确确认与状态校验，不做装饰性简化。

T5：弹窗/抽屉

  • 使用 Element Plus 对应控件，统一外壳；原有业务逻辑分批接入，不一次性重写所有表单。
  • 简单确认宽 480px，普通编辑 720px，复杂编辑 960px，均受视口减 32px 限制；上限高度为视口减 32px。
  • 标题、正文、底部分区；标题与底栏 padding 12px，正文 12px；只有正文滚动。复杂全屏式编辑才使用 T4，不能同时两套操作栏。
  • 按钮间距 8px，取消在前、主操作在后；危险行为写明对象与后果，不预选危险按钮。
  • 焦点进入弹层，关闭返回触发入口；忙碌时防重复提交，错误可读、可恢复。
  • 下拉/日期弹出层从统一主题桥接获得颜色与字体；不得被全局 table、button 规则污染。

T6：业绩看板

复用 T1 筛选卡片与二层操作区；下方 KPI、图表、明细区块间距 8px，卡片内部 12px。看板无需新增重复的大标题。数据来源、时间范围、币种与时区沿用现有真实口径；加载/空态保持尺寸，禁止为视觉填充虚构图表数据。

  • 小计数值与结算数值来自同一实际订单计算；不增加一套 UI 金额计算。
  • 两侧底栏同高、同顶、同底；checkout 占满右侧底栏，无额外白色垫边。禁止将两个面板的底栏合成一个共享条。

不为使用模板而引入无业务需求的权限中心、云端路由、演示接口。采用上游代码时记录来源、固定提交与许可证要求；本文件不替项目选择开源许可证。若完整替换框架会改变路由、状态或构建架构，需另列迁移方案确认。

7.2 唯一样式来源

拟按“基础变量 → Element Plus → 主题桥接 → 布局模板 → 业务例外”的明确层级管理；实际 import 顺序在实施时固定并记录。

  • 尺寸变量一处定义；主题只映射颜色；公共布局一处定义；组件内部只保留业务特有结构。
  • 清理已被模板替代的旧规则，而非继续在 workbench.css 尾部追加同名覆盖。
  • 后台用明确作用域，POS 与打印分开；禁止全局 button、table、h2 改写 Element Plus 弹出层。
  • 不以大量 #app、!important、负 margin 或加载顺序碰巧生效作为最终方案。
  • 本文拟定组件名或变量名不意味着需要立即创建全部文件；以最少公共实现承载所有同类页面。
  • 设计例外必须登记“页面、原因、差异值、验收方式”；没有登记的页面级 padding 覆盖应被移除。

8. 响应式与交互验收

768×1024检查两栏最小宽与长文本；不以缩小字体保布局

  • 后台页面正文只能有明确的滚动所有者：列表滚动主体，表单滚动正文；页面壳、嵌套 div 不能同时截断内容。
  • 展开更多查询后表格高度自然减少，合计/分页仍可达；矮屏无法容纳时允许外围滚动兜底，不能盖住数据。
  • 中文、英文、意大利语至少各验一次长按钮、日期、货币和类别名；标题不单字换行，操作可按组换行。

  • 减少动态效果设置生效；保留必要的短切换，避免测量动画中途作为最终对齐结果。

8.1 可量化检查

  1. 动画结束后，各后台模板左边界与公共工作区内容左边界误差 ≤ 1 CSS px；右边界同样检查。
  2. 列表页顶部不出现与标签重复的大标题或空标题占位；设置操作栏与正文 gap 为 0，边界仅一条 1px 线；分离区块 gap 为 8px。
  3. 输入/选择/日期/主操作外高为 36px，误差 ≤ 1px；不要只检查内层 input。
  4. POS 两面板顶底差 ≤ 1px，底栏均 64px；检查空购物车、1条、多条及长名称。
  5. 列表 0、1、满页、多页、筛选无结果时分别检查合计和分页位置。
  6. 三种主题下分别检查 header、容器 padding 区、弹层和 disabled 状态，不出现异色色带。
  7. 批量部分失败、导入失败、保存失败、设备返回失败均有明细且可继续操作；不靠 CSS 隐藏错误。
  8. 视觉截图/DOM 尺寸证据与业务测试分开记录；构建成功不能替代浏览器验收。
