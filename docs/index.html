单机开源版 · 1.0.0

门店收银，在本机完成。

商品、现金订单、退货与经营看板。无需云端账号，业务数据保存在当前浏览器。

面向独立门店收银员与二次开发者。Vue 3 + TypeScript + Element Plus；界面沿用现有管理台规范，保留 POS 左右独立操作区域。

范围开源版
现金收银、挂单、找零、小票本地使用
商品、分类、批量启停、Excel本地使用
订单创建、导入、退货、看板本地使用
JSON 备份、语言、主题、快捷键设置本地使用
会员资产、扫码支付、门店与员工、云端仅 Upgrade 占位，无对应业务实现
库存、采购、调拨、多端同步不在开源版范围

快速开始

需要 Node.js 22.19+、npm 和 Git。使用支持 IndexedDB、ES2022 和原生 dialog 的现代浏览器。

Git 源码仓库↗。默认开发分支为 main；已有源码的开发者直接在前端目录安装依赖。

1. 获取并运行源码

# 克隆项目
git clone --branch main https://github.com/cd-ro-tech/ro-pos.git ro-pos

# 进入项目目录
cd ro-pos/ro_eshop_pos_vue

# 按锁文件安装依赖
npm ci

# 启动开发服务
npm run dev -- --port 5182

2. 完成本机设置

访问 http://127.0.0.1:5182/，点击“单机版 · 无需登录”，按向导选择币种并准备商品。文档入口为 /docs/index.html。已有商品或订单后不能直接改变本机币种。

当前应用版本为 1.0.0。

收银操作

  1. 点击商品，或扫描条码加入购物车。
  2. 选中购物车行，调整数量或价格；需要暂存时点击“挂单”。
  3. 点击结算，输入现金实收，核对找零后确认。
  4. 本机保存成功后查看小票；浏览器打印能力取决于系统与打印机配置。

收款请求有唯一标识，同一请求重试不会重复登记。订单保存与打印分别处理，打印失败时先核对订单，再补打小票。

挂单、购物车与快捷键属于当前浏览器。开源版不查询、不扣减库存，也不承诺可售库存数量。

订单创建与导入

在工作台 → 订单管理，选择“创建订单”或“导入订单”。两种方式都先创建待付款订单，不会直接计入实收。

  1. 手工选择已有商品；或下载 Excel 模板填入商品条码、数量与单价。
  2. 点击“预览校验”，检查每一行的结果。会员列仅兼容旧模板，必须留空。
  3. 同一导入单号的多行合为一单；重复商品请先合并数量。
  4. 确认后创建待付款订单，在详情中完成现金收款或关闭订单。

一次最多 500 行商品明细、50 张订单，文件最大 5 MB。相同导入单号重复提交不会重复建单，内容不一致会报错。批次部分成功时保留结果，只继续提交未完成订单。

退货与统计

使用本机小票号查找已收款订单后办理退货。退货不会恢复库存；本版本每张小票只允许办理一次退货。看板实收按收款时间统计，退款单独展示；不同币种分开查看。

商品与分类

项目说明
列表与批量操作商品资料与分类都支持列表勾选、批量启用、批量停用以及 Excel 导出。批量操作不满足条件时，结果对话框列出对应记录与原因。
分类与可售校验商品只能放入末级分类。条码与编码用于精确检索，导入时会校验重复、金额和分类引用。停用商品或其所属分类后，该商品不能继续被新订单结算。
导出与备份Excel 导出根据页面勾选记录生成；JSON 备份用于完整迁移。两种文件用途不同。

数据备份与恢复

工作台 → 数据管理 → 导出 JSON。将文件保存在安全位置，定期在独立浏览器环境验证恢复。

浏览器存储不等于永久备份。清除网站数据、使用隐私模式，或更换协议、域名、端口、浏览器配置文件，均可能使原数据不可见或丢失。

开源版使用独立 IndexedDB 数据库 ro-pos-opensource-v1。原版本数据不会自动迁移；使用符合单机范围的 JSON 备份导入。

导入先校验再合并，相同标识的冲突会报错。含会员资产、积分、钱包或非现金交易的备份会明确拒绝，不会自动丢弃不支持的数据。商品币种不同不能直接合并。

操作执行顺序
日常备份导出 JSON → 安全存放 → 在独立环境验证恢复
恢复数据预览校验 → 核对冲突 → 确认合并
清空数据先导出并验证备份 → 输入确认文字 → 执行清理

清空数据需要输入确认文字。执行前先导出并验证备份。

本机设置

项目说明
本机偏好支持小票、主题、语言、币种和快捷键设置。
小票打印使用浏览器打印与补打，打印机由浏览器及系统配置。
版本范围不包含设备设置、钱箱、客显或本机设备桥接。升级入口仅显示说明，不执行在线收款。

编码规范

下列是新代码与贡献应遵守的规范。现有代码仍含部分 any 和紧凑写法，尚未全量按此整理；当前未配置 ESLint / Prettier 检查，不将格式统一描述为已自动保证。

文件、命名与类型

规范项实施要求
命名与文件Vue 组件使用 PascalCase.vue，业务模块使用 camelCase.ts；变量和函数用 camelCase，类型用 PascalCase。既有数据契约中的 snake_case 字段保持兼容。
组件与类型组件采用 <script setup lang="ts">，新 props、事件、业务参数和返回值给出明确类型；外部输入先用 unknown 校验后收窄，避免扩散 any。
输入边界使用项目已有相对路径导入。遵循所改文件格式，不为无关排版制造大范围差异；职责变化时再拆模块。

分层与数据一致性

  • 页面负责交互与展示；领域模块负责金额、状态和校验；存储模块负责事务。组件不直接拼接设备协议，也不绕过业务入口修改账本。
  • 金额使用现有计价与舍入方法。不要把页面显示合计直接当作最终账本金额，也不要新增未定义的币种精度规则。
  • 写操作在事务内完成校验和更新，重复请求沿用原 UUID。不要吞掉异常、把失败显示成成功或使用默认假值掩盖缺失字段。
  • 修改持久化格式时同步迁移、备份校验和兼容测试；必须保留原记录的真实来源与状态。

界面与国际化

规范项实施要求
模板与主题沿用项目 UI 设计规范和共享组件；颜色使用 theme 变量，间距遵循现有页面规范，不散落主题色硬编码。商品卡片内部设计保持原约定。
文案与可访问性用户可见文字走 t()，业务字段翻译走现有翻译逻辑；按钮用原生 button，表单有标签，弹框支持键盘关闭和焦点操作。
交互与验证交互覆盖加载、空数据、错误、重复点击和禁用状态；修改后分别检查蓝、橙、黑金主题及窄屏，说明实际验证范围。

本地 API 与事务

src/api.ts 暴露 api(operation, values, options)。这是浏览器内的异步函数调用，不是 HTTP 服务：它动态加载 standalone.ts 并调用 standaloneApi。入口先执行 assertLocalEdition 检查版本范围。

操作用途关键参数
products / categories读取本机商品与分类按对应操作处理查询参数
quote核算价格与可售资格order_line
create_order创建待付款订单request_key, order_line, currency_code, note
pending_cash现金收款order_id, request_key, received
pending_close关闭待付款订单order_id
import { api } from './api';

// id 必须来自当前本机商品；创建请求的 UUID 在重试时保持不变。
const requestKey = crypto.randomUUID();
const payload = {
  request_key: requestKey,
  currency_code: 'CNY',
  order_line: [{ id: selectedProduct.id, qty: 1,
    sale_price: selectedProduct.sale_price }],
  note: '手工建单'
};
const receipt = await api('create_order', payload);

事务与重试

offline.ts → mutate(key, update) 在同一个 IndexedDB readwrite 事务内读取、校验并写回账本，事务完成后才返回成功。不要在业务页面拆成独立的 read 和 write，否则并发标签页可能覆盖更新；更新回调应保持同步。

创建订单使用 UUID request_key 去重，同一标识对应不同内容会拒绝。收款保存 payment_key；相同收款标识和相同实收金额重试返回原结果。不同标识不能再次结算已完成订单。不要在重试时重新生成标识。

订单状态

draft ── pending_cash ──→ done
  └──── pending_close ─→ closed

paid_at 记录收款时间；at 记录创建时间。兼容旧记录时，缺少 state 的订单按已收款处理。现金金额当前最多两位小数，实收不得小于应收；多币种名称不代表支持任意小数精度。

数据模型与备份格式

IndexedDB 数据库为 ro-pos-opensource-v1，数据库结构版本为 1，对象仓库为 records。账本键名 standalone-ledger-v1 与备份数据版本不是同一个概念。

{
  "format": "ro-pos-standalone",
  "version": 7,
  "installation": "<本机生成的 UUID>",
  "currency_code": "CNY",
  "categories": [],
  "products": [],
  "orders": [],
  "members": [],
  "member_rules": {},
  "member_entries": []
}

以上为结构示意，不是可直接导入的备份。兼容字段 members、member_rules、member_entries 不代表开源版提供会员资产业务。请使用程序导出的文件；导入校验会拒绝超出本地现金版本范围的数据。

实体主要字段关联
分类uid, id, name, parent_uid, active通过父分类 UID 建立层级
商品uid, id, name, barcode, default_code, sale_price, category_uid引用分类 UID
订单uid, number, state, at, paid_at, currency_code, lines, amount, received明细保存商品 UID 和成交快照

previewLocalImport 预演合并，importLocalData 在事务内再次校验并执行。冲突抛错时事务回滚，不应由页面忽略错误后继续写入。修改备份结构时需同步版本迁移、校验和往返测试。

JSON 账本备份不等于浏览器全量备份：主题图片等本机偏好不在上述账本范围。打印设置需在目标机器重新核对。

部署与离线缓存

生产构建为静态网页，无需部署云端 API。当前 Vite 使用默认根路径，建议在独立域名或子域名的根目录托管完整 dist/。放入子目录前，需要适配 Vite base、资源地址和 Service Worker 作用域并重新构建。

npm ci
npm run typecheck
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 5182

vite preview 用于本地验收；生产使用 HTTPS 静态服务器。不能用双击 index.html 的方式代替应用部署。独立文档 HTML 可直接打开，但剪贴板能力取决于浏览器安全上下文。

offline-worker.ts 根据构建资源生成 sw.js 和带版本的缓存名。首次安装时预缓存应用资源；应用首页导航优先联网，网络失败时回退到缓存。新 Worker 激活时清理旧的应用缓存，不负责备份 IndexedDB。

升级部署应先备份账本，完整上传构建文件，并在隔离浏览器验证新旧缓存切换、刷新与断网启动。首次加载失败、缓存被清除或浏览器清理网站数据时，不能承诺离线可用。

二次开发约定

  1. 操作页放在 operate/，后台页按业务放入 backend/。共享控件与领域逻辑分开。
  2. 新操作在本地调度层加入参数校验；涉及账本写入时使用事务，不从页面直接修改持久化记录。
  3. 修改订单逻辑时覆盖金额精度、状态转换、重复提交、停用商品/分类和导入冲突。
  4. 修改持久化结构时提供迁移与备份兼容校验；测试使用隔离数据，不连接真实门店账本。

以下命令在 ro_eshop_pos_vue 目录执行。

# 类型检查
npm run typecheck

# 自动测试
npm test

# 类型检查并构建生产版本
npm run build

# 本地预览生产版本
npm run preview -- --port 5182

构建结果位于 dist/。生产部署、子目录适配与 Service Worker 缓存见部署文档。项目没有 npm run lint 脚本；不要套用其他模板的命令。

常见问题

换端口后为什么没有原来的数据？

浏览器按来源隔离存储。返回原地址导出 JSON，再到新地址导入。

为什么会员或云端入口只有 Upgrade？

这些功能属于其他版本，不包含在本开源源码中；占位用于说明产品范围。

创建或导入订单后，实收为什么没有增加？

订单当前为待付款。完成现金收款后，才进入对应收款日期的实收统计。

可以商用吗？

GPL 不禁止商用。分发或二次开发发布时仍需遵守许可证，品牌与第三方素材另行核实。
